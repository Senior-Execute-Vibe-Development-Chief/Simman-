## FIXED in this audit (code)

1. **War-sack captives were thrown away (A, HIGH).** Under the default tile-war the storm
   wrote `recordCaptives(att,…)` and `att._captives` onto the transient per-pass country
   ADAPTER — discarded at end of pass — while `dS.people -= taken` still ran. War supplied
   ZERO slaves (the "war as the primary supply of the slave trade" comment sat over dead
   code) and ~`CAPTURE_FRAC` of every stormed capital's people leaked from the world.
   Also the slave-market pull keyed off `adapter.id` (a countryId — the wrong key space
   for `_slaveScarcity`), degrading to base pull. Fix: the CAPTOR is the victor's real
   capital (`att._capital`), mirroring the existing `def → def._capital` conversion.
   (armies.js, the storm block.)
2. **Nomad attrition inconsistency (A).** `techMul(adapter)` read `adapter._nomad` as
   undefined, dropping the steppe-cavalry factor its own `_M` bakes in per member — nomad
   realms bled extra casualties. Fix: adapters carry the army-weighted member `_nomad`.
3. **War advanced at ¼ the real rate on the shipped grid (F, HIGH).** The tile-capture
   budget (`MAX_CAPTURE`, `CAPTURE_SCALE`) carried NO resolution factor while its peer —
   peaceful expansion — is explicitly res-invariant (`EXPAND_RATE·resScale³`). The war
   pass fires at a fixed tick cadence (unlike the rNorm-thinned territory pass), so the
   correct compensation is ×resScale²: at 960px the war machine swept real km²/history at
   ~¼ the validated 240-tile-reference rate (every consolidation probe in this repo runs
   at the reference — the shipped app was quietly a different war regime). Momentum banked
   and front-displacement (stalemate EMA) are normalized ÷resScale² back into
   reference-tile units so `MOMENTUM_CAP`/`STALE_EPS` keep one meaning at every grid.
4. **REALM_GAP_FILL and MARKET_RANGE were raw tiles among res-scaled peers (F).** Gap-fill
   closed only half the real no-man's-land width at 960; the market-pull kernel clustered
   settlements at half the real distance while the founding spacings beside it scale.
   Both now ×resScale/rn (×1 exactly at the reference — byte-identical where validated).
5. **Six stale/misleading lever descriptions (B/D).** `PERSISTENT_TERRITORY` (def-1
   "DEFAULT" but UNREAD under the field polity — the map is persistent by construction),
   `ORG_APT_CAP` (the aptitude→capacity payout is wired only into the skipped legacy
   path), `CLAIM_POW` (legacy-only), `ENCIRCLE_PENALTY` (octant scan dropped in tile-war
   v1, never restored — the lever does nothing at any setting under defaults),
   `ANCHOR_POP` (described its =1 path as clock-keyed; it was de-clocked to the emergent
   `_civYear` long ago), `SOIL_EXHAUST`/`TROPIC_SPARSE` (rationalized via the
   default-off anchor). All now state the truth about the default regime.
6. **Stale docs that would mislead a future session (D).** probe_warbars' header still
   declared the amphibious gap OPEN (restored long since — the same file's findings said
   so 40 lines later); SPEC-climate-moisture-fix read as an open handoff though
   moistureSolver ships the prescribed conserved transport; territory-growth-plan's
   header said "plan / pre-build" over a body saying SHIPPED; state.js said "two hearths"
   above a three-entry list; README said "two villages"; review-2026-07-civ-engine now
   carries a staleness warning (several CONFIRMED items since fixed, others unverified);
   country-count-size-diagnosis now notes `SIM_REACH_*` are dead knobs under the field
   polity; crystallize's FRONTIER_EXTEND_DIST comment argued "ABSOLUTE (NOT res-scaled)"
   above code that (correctly) scales ×rn; field-polity-spec §4c header un-stale'd.

## OPEN — real mechanism gaps (documented, deliberately NOT quick-fixed)

1. **§4b — birth at population-field peaks** (field-polity-spec): `nucleateFrontierStates`
   still seeds realms from settlement clusters with no `TILE_POLITY` branch — countries
   still "spawn with" settlements. The designed fix (seed at an unclaimed popField
   maximum) remains unbuilt.
2. **Per-country encirclement** (tile-war v1 dropped it): needs a design pass (octants
   around a NATION are not octants around a settlement), then measurement. Until then the
   lever is honestly labelled legacy-only.
3. **Irredentist casus belli is inert under tile-war**: the adapter has no `culMix`, so
   the "liberate a co-national province" bar-discount reads 0. The honest local read
   needs the per-tile identity field — today a render-only, lens-gated mirror
   ("nothing reads the field", identityField.js). Passing the defender's capital instead
   would be linearly redundant with the base people term (sgn = 1−2·mixShare of the same
   pair) — painting the effect. Wire it when identity Stage 2 makes the field
   always-on/authoritative. (Commented at both call sites in armies.js.)
4. **ORG_APT_CAP's capacity payout**: wire aptitude into the field model's Tilly
   hold-capacity (conquest.js) — the learning half already works.
5. **Residual F-class items (steelmanned, lower stakes):** `ASSAULT_MARGIN` +
   `coreRadiusFor` storm radius (flat tiles — partly topological: the siege line touches
   the drawn city footprint, which is also unscaled); `HINTERLAND_BY_TIER` guaranteed
   belt; `UNREST_RADIUS_MIN` flat floor (rarely binds); `BORDER_SMOOTH` pass count
   (cosmetic); controlField's CTRL_LIVE reach/fade constants (experimental, off).
6. **The review-2026-07 save/load family** (B19 road-flow decay after load, B42
   reconcile-vs-pass-start "Dissolved" mislabels, B52/B75 `_riverAcc` lost on load) was
   NOT re-verified either way by this audit — a dedicated load-persistence pass is the
   next audit axis if those symptoms matter.
7. **Coalition armies still don't combine on shared fronts** (from the WAR_REACH work):
   the other historical hegemon-killer; per-dyad force allocation fights allies' wars
   separately.
