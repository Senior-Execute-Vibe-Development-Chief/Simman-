## Context in three sentences

This repository contains Simman v1 (a working emergent-civilization sim,
now frozen as reference) and, in `spec/`, the complete design for a
ground-up v2 rebuild: a realistic global history simulator on real Earth.
The build proceeds by gated milestones (`spec/10-build-plan.md`); M0 is
the harness that makes everything after it provable — determinism,
hashing, gates, CI — and contains **zero simulation physics**. Your job
is M0 alone, built to the letter of the spec, with questions recorded
rather than guessed at.

## Deliverables

### 1. Workspace

```
v2/
  package.json            # standalone; scripts below
  src/sim/                # sim core (worker + node isomorphic)
  src/shell/              # (placeholder dir + index.html stub only in M0)
  src/ported/             # verbatim v1 ports live here, cited
  rust/router/            # Rust crate → wasm (see #7)
  tools/                  # harness CLIs
  data/reality/           # empty + README stub (datasets arrive at M1+)
  QUESTIONS.md            # your questions log (see ground rules)
  README.md               # commands, layout, how to run every gate
```

Scripts (names matter — they become the standing culture):
`npm run smoke` · `npm run bench` · `npm run lint` · `npm run test` ·
`npm run build`.

### 2. RNG (port, byte-compatible)

Port `src/sim/peopleSim/rng.js` (v1, repo root) to
`v2/src/ported/rng.ts` preserving behavior EXACTLY: `hash32`, `mkRng`
(sfc32 construction), `passRng(seed, systemName, step)`,
`entityRng(seed, systemName, entityId)`. The discipline it encodes — no
shared sequential stream, stateless substreams, no RNG state in saves —
is constitutional. **Test**: golden vectors — generate outputs from the
v1 JS for a fixed input set (script it against v1's file directly) and
assert the TS port reproduces them bit-for-bit.

### 3. Deterministic math

`v2/src/sim/dmath.ts`: our own `dsin`, `dcos`, `dexp`, `dln`, `dpow`
(polynomial/table implementations — accuracy ~1e-9 is fine, *bit-stable
everywhere* is the requirement). **Lint**: an eslint rule (e.g.
`no-restricted-properties`) forbidding `Math.sin|cos|tan|exp|log|pow|
atan|atan2|asin|acos|sinh|cosh|tanh|random` anywhere under `v2/src/sim`
(`Math.sqrt|abs|min|max|floor|ceil|round|trunc|sign|hypot`? — hypot NO
(implementation-varied); sqrt/abs/min/max/floor/ceil/round/trunc/sign
are IEEE-exact and allowed). `Math.random` is forbidden everywhere in
`v2/src`. **Test**: golden bit-values for dmath functions across the
domain, asserted identical in Node and all three browsers (see #8).

### 4. World skeleton, hash, save/load

- `v2/src/sim/world.ts`: a minimal `World` — seed, config object, grid
  dims (two named grid presets: `dev` and `target` — sizes from
  `02-architecture.md`; land mask left empty/all-land placeholder), a
  registry of typed-array fields declared via ONE field-list module
  (`fields.ts`) that drives allocation + hash + save + load from a
  single declaration (v1 persist.js's architecture — see its header for
  the pattern; do not port its 67 version guards).
- `hashWorld(world)`: stable 64-bit-ish hash over the declared fields +
  config. Config identity is part of world identity.
- Save/load: JSON envelope + typed arrays (base64 or binary chunks);
  **save→load→save must be byte-identical** (test).
- A placeholder tick (`stepWorld`) that exercises the machinery
  honestly: advances step, draws from `passRng`, writes a trivial
  noise-decay field via dmath. Clearly marked `M0-PLACEHOLDER` — it
  exists so determinism tests test something, and it is deleted at M1.

### 5. Collector skeleton

`v2/tools/lib/collect.ts`: introspective metric collector over the World
— every numeric leaf measured by default; fail-open exclusion list
(`WORLD_SCRATCH` exported from the collector itself); `.n` on
distributions; flat `name → number` map. Reference: v1
`tools/lib/simmetrics.mjs` (read its conventions; port the *pattern*,
not the v1-specific namespaces).

### 6. The smoke gate

`v2/tools/smoke.ts` (run via `npm run smoke`), all checks hard-fail:
1. **Determinism**: same seed, N=500 placeholder ticks, run twice →
   identical `hashWorld` — at BOTH grid presets.
2. **Save/load**: mid-run save; load; hash equality; continue both 100
   ticks → hashes still equal.
3. **Conservation harness**: the balance-sheet assertion machinery
   (sources/sinks ledger per conserved quantity) wired and asserting
   zero unexplained flux on the placeholder field (which must be written
   through it).
4. **Provenance stamp**: every tool prints git hash + dirty flag + seed
   + grid + config digest on start (v1 harness lesson — stale-tree
   findings nearly got published twice).

### 7. Wasm toolchain bootstrap

`v2/rust/router/`: a Rust crate (wasm-bindgen + wasm-pack) exposing ONE
function for now: Dijkstra over a small hardcoded test graph with f64
costs, returning distances. Built to wasm, loaded from TS in both Node
and browser. **This is a toolchain proof, not the routing engine** — the
CRP engine is M1 work. **Test**: identical output arrays (bitwise) from
Node + all three browsers.

### 8. Tri-engine CI

`.github/workflows/v2-ci.yml`: on push touching `v2/**` — lint, unit
tests, smoke (Node), then a Playwright job running the smoke
determinism + dmath goldens + wasm test inside **Chromium, Firefox, and
WebKit**, asserting all four environments (3 browsers + Node) produce
the identical world hash and goldens. This gate is the product's
seed-sharing promise; treat any engine divergence as a hard failure to
investigate, not to waive.

### 9. Constants-ledger lint

`v2/tools/ledger-lint.ts`: scans `v2/src/sim` for numeric literals
outside a whitelist (0, 1, 2, array indices, bit ops) that are not
imported from `v2/src/sim/constants.ts`; every entry in `constants.ts`
must carry a comment citing its row in `spec/09-constants-ledger.md`.
Naive first version acceptable; wired into `npm run lint`.

### 10. Perf bench harness

`v2/tools/bench.ts`: ms/tick over the placeholder at both grids, JSON
output with provenance. No budgets enforced yet (they arm at M1) — the
harness and its output format are the deliverable.
